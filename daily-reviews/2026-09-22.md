## Anomaly: a spurious `missed_entry` from a real date bug in `seedSymbol()`

At startup (13:30:19 UTC), the agent logged:
```
missed_entry CRML barTime=2026-09-21T19:55:00.000+0000 price=9.215 volume=494450
```
That `barTime` is **yesterday** (2026-09-21) at 3:55pm ET — the tail end of Monday's session, not this morning's pre-open window. Checked `main.ts`: `isAtOrAfterMarketOpen(date)` only compares hour/minute (`nyTimeOf`), never the calendar date:

```ts
function isAtOrAfterMarketOpen(date: Date): boolean {
  const { hour, minute } = nyTimeOf(date);
  return hour > 9 || (hour === 9 && minute >= 30);
}
```

`seedSymbol()`'s 30-bar lookback apparently reached back far enough (no overnight bars exist) to include a bar from the previous session's close. Since 3:55pm ET's time-of-day is `>= 9:30am`, that stale Monday bar got classified as "session" instead of "pre-open" and was replayed through the real `onBarClose()` signal path — producing a `missed_entry` log line for a crossover that's a full trading day stale, not a real opportunity this morning. This didn't cost anything (missed-entry replay is log-only by design, never auto-traded), but it's a genuine bug in the pre-open/session split, not just a log curiosity: the same mechanism could in principle misclassify bars on any day where the 30-bar window crosses a session boundary. Worth a proper fix (compare full date, not just time-of-day) since it currently makes `missed_entry` entries after a gap unreliable.
